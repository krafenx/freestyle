# Как запустить (с нуля до работающего бота)

Пошагово, с ожидаемым результатом на каждом шаге. Всё делается из папки `vip-bot/`.
Подробности про крон — в [`vip-bot/docs/cron.md`](vip-bot/docs/cron.md).

---

## 0. Что нужно один раз

1. **Node.js 18+** — `node -v`.
2. **Serverless включён у бота.** @BotFather → твой бот → **Settings** (или главное меню бота) →
   **Serverless** → включить. Ранний доступ: иногда нужно подождать подтверждения.
3. **CLI-токен.** @BotFather → твой бот → **Serverless → CLI Access** → скопировать access token.
   Он выглядит как `app12345:abcdef…`. **Это не токен бота** (`12345:AAE…`) — их легко перепутать.
4. **(для крона)** файл `.github/workflows/vip-reminders.yml` должен быть в `main`.

---

## 1. Деплой кода и таблиц

```bash
cd vip-bot
npm install                  # ставит @tgcloud/cli
npx tgcloud login            # вставить CLI-токен (интерактивно)
npx tgcloud push             # код в облако

# push НЕ меняет базу — схема применяется отдельной командой:
npx tgcloud migrate          # создать таблицы vip_grants / notifications / audit_log / settings
```

Ожидаемо: `push` показывает список загруженных модулей, `migrate` — какие таблицы и индексы
создаются (и просит подтверждение).

Проверить, что webhook платформы на месте:

```bash
npx tgcloud webhook          # должно быть "in sync"
```

Если `push` ругается на токен — значит вставился обычный токен бота, а не CLI-токен.

**Без интерактивного логина** (например, на сервере): `TGCLOUD_TOKEN=app12345:xxx npx tgcloud push`.

---

## 2. Первый запуск в Telegram

1. Открой своего бота в Telegram (личка или приватная группа модераторов — где удобно).
2. Отправь `/start`.

Ожидаемо: бот отвечает «👋 Ты первый — записал тебя владельцем и этот чат как чат для
напоминаний» и справкой. С этого момента **этот чат** — получатель всех напоминаний.

> Если бот ответил «нет доступа» — значит владельцем уже стал кто-то другой (например, ты сам
> при тестовом запуске через `tgcloud run`). Лечится сбросом настроек:
> `npx tgcloud run endpoints/dev-reset`, потом снова `/start`.
> Себя и коллег проверить: `/vip whoami` (покажет твой tg id).

---

## 3. Проверка, что учёт работает

```bash
# локальные проверки, платформа не нужна
npm test                     # 32 теста: даты, DST, T-3/T-1/T-0, догон, дедуп
npm run smoke                # все модули импортируются
```

В боте:

```
/vip add @nick               → «записал: @nick — VIP на 30 дн., до 04.12.2026» + команда /vip nick
/vip list                    → список с датами
/vip info @nick              → история
/vip check                   → «🔄 проверил: напоминаний 0» (ручной прогон тика)
/vip dashboard                → запиненное сообщение, которое бот сам обновляет
```

Дальше выдай VIP в чате канала и жди напоминаний.

## 4. Крон (напоминания «сами»)

Расписание раз в час: `.github/workflows/vip-reminders.yml`.

```bash
gh secret set TGCLOUD_TOKEN --repo <owner>/<repo>       # вставить CLI-токен
gh workflow list --repo <owner>/<repo>                  # в списке должен быть vip-reminders
gh workflow run vip-reminders --repo <owner>/<repo>     # ручной запуск для проверки
gh run list --workflow=vip-reminders --limit 3          # success?
```

Ожидаемо: job зелёный, в логе строка вида `проверил: напоминаний 0`. Без секрета запуск тоже
зелёный, но с пометкой «тик пропущен» — это нормально до того, как вставишь токен.

Альтернатива без GitHub (VPS, Raspberry Pi, старый ноут):

```bash
cd vip-bot && chmod +x scripts/tick.sh
mkdir -p ~/.config/vip-bot && printf '%s' 'app12345:xxx' > ~/.config/vip-bot/token && chmod 600 ~/.config/vip-bot/token
crontab -e     # 0 * * * *  /полный/путь/до/vip-bot/scripts/tick.sh >> /tmp/vip-bot.log 2>&1
```

## 5. Что дальше живёт само

| Когда | Что происходит |
|---|---|
| T−3, T−1 | тихое напоминание с кнопками и готовой `/unvip ник` |
| T−0 после 10:00 (пояс из настроек) | «истекает сегодня» |
| T+1 и далее раз в неделю (до 4 раз) | «просрочено — сними», с догоном, если бот спал |
| понедельник 10:00 | дайджест «на этой неделе истекают» |
| после любого сообщения боту | дашборд пересчитывается |

Кнопки: **✅ Снял** (закрыть запись), **➕ +30 дн.** (продлить от текущего конца),
**📅 +7 дн.**, **🙈 Оставить** (напомнить через неделю), **⏰ Завтра**.

## Если что-то не работает

| Симптом | Причина |
|---|---|
| `push`: ошибка авторизации | вставлен токен бота вместо CLI-токена (нужен `app12345:…`) |
| бот молчит в Telegram | не сделан `push`; или `npx tgcloud webhook` показывает расхождение — `npx tgcloud webhook sync` |
| бот отвечает «нет доступа» | владельцем стал другой id → `npx tgcloud run endpoints/dev-reset`, затем `/start` |
| `migrate`: таблиц нет после `push` | это норма: `push` базу не меняет, нужен отдельный `migrate` |
| напоминаний нет, хотя срок подходит | нет крона И никто не писал боту; либо запись не попала в окно (T−3/T−1/T−0/просрочка) |
| крон в Actions не появляется | workflow лежит не в `.github/workflows` корня репозитория, или не смержен в `main` |
| тик падает с `тик не выполнена: нет chatId` | боту не написали `/start` после деплоя |
