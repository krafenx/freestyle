# Готовый промпт для агента/разработчика

Самодостаточное ТЗ под **Telegram Serverless** (tgcloud). Скопируй целиком, подставь
значения в `{{...}}` из блока «КОНТЕКСТ». Если поле не заполнено — агент берёт дефолт
из раздела «Дефолты» и не переспрашивает.

> Расширенная версия этого же ТЗ уже реализована в [`../../vip-bot/`](../../vip-bot/) —
> промпт можно использовать, чтобы переписать проект с нуля, расширить его или
> проверить чужую реализацию на соответствие требованиям.

---

## ПРОМПТ (копировать отсюда)

**Роль.** Ты senior-разработчик, который делает небольшие продакшн-боты на JavaScript
под Telegram Serverless. Ты пишешь код, который человек откроет через полгода и поймёт:
без магии, с тестами на критичную логику, с понятными сообщениями об ошибках в чат.

**Задача.** Бот учёта Twitch-VIP, выдаваемых на срок (по умолчанию 30 дней): помнит,
кому и когда выдан VIP, считает дату окончания, присылает напоминания модераторам и
ведёт историю. Работает на Telegram Serverless со встроенной SQLite.

### КОНТЕКСТ

- Канал Twitch: `{{CHANNEL_LOGIN}}`; чат модераторов в Telegram: `{{приватная группа / личка}}`.
- Заказчик — **модератор**, не владелец канала. Токена стримера у нас **нет и не будет**.
- Срок VIP: `{{30 дней}}`. Продление: `{{стопкой: от текущего конца срока}}`.
- Выдача: `{{вручную командой /vip в чате Twitch после записи в боте}}`.
- Пользователи бота: `{{2–3 модератора}}`, доступ по whitelist `tg_user_id`.
- Часовой пояс отображения: `{{Europe/Moscow}}`, час напоминаний: `{{10:00}}`.
- Внешний «будильник»: `{{GitHub Actions раз в час, опционально}}`.

### ЧТО ПЛАТФОРМА УМЕЕТ И ЧЕГО НЕ УМЕЕТ (это не советы, а ограничения)

1. **Нет таймера.** Код исполняется только на апдейт Telegram или на вызов модуля через
   `npx tgcloud run`. Значит напоминания делает функция `runTick()`, которую дёргают
   из трёх мест: ленивый тик в `handlers/*`, `endpoints/tick` (внешний крон), кнопка
   «Проверить». Никаких `setInterval`/`setTimeout`-планировщиков.
2. **Нет произвольного входящего HTTP.** Вебхуки Twitch (EventSub) принять нельзя —
   не проектируй их. Источник правды по выдачам: команда модератора в Telegram.
3. **Нет npm-пакетов и файловой системы.** Только `sdk` и свои модули. Даты и часовые
   пояса — на `Intl`, не на Luxon/date-fns.
4. **Нет внешних ключей** в SQLite; `.references()` бросает исключение. Целостность —
   в коде, физических удалений нет (только смена `status`).
5. **Нет загрузки/выгрузки файлов.** Экспорт CSV — текстом в `<pre>`, порезанным по
   ~3500 символов (лимит сообщения 4096).
6. **Webhook'ом управляет платформа.** Никогда не вызывать `setWebhook` сырым токеном бота.
7. **Лимиты:** ~3 с CPU на вызов, ~0.5 ГБ SQLite, ответы ограничены по размеру.
   Тик должен читать только открытые записи, а не всю таблицу.

### ЖЁСТКИЕ ТРЕБОВАНИЯ

1. **Никаких авто-действий в Twitch.** Бот не выдаёт и не снимает VIP: Helix требует
   токен стримера (`broadcaster_id` = владелец токена), токен модератора получает 401/403.
   Вместо действия бот отдаёт готовую команду `/vip nick` / `/unvip nick` для копирования
   (моноширинным блоком) и кнопки подтверждения.
2. **Идемпотентность прежде всего.** Перед отправкой напоминание «столбится» записью в
   журнале с `UNIQUE(grant_id, kind)`; повторный тик молча пропускает. Это единственная
   защита от дублей, когда триггеров три.
3. **Время в базе — только UTC** (`mode: 'timestamp'`), рендер — в целевом поясе через
   `Intl`. Сравнение сроков — по локальным календарным дням, а не по «24 часам».
4. **Импорты по bare-имени:** `from 'sdk'`, `from 'schema'`, `from 'lib/core'`.
   Относительные пути и `.js` — ошибка сборки на платформе.
5. **Чистое ядро.** Вся логика дат, разбора команд и выбора напоминаний — в одном модуле
   без `sdk` (`lib/core.js`), чтобы её можно было гонять `node --test` без платформы.
6. **Whitelist доступа.** Любой апдейт от чужого `from.id` (включая callback) получает
   отказ и запись в лог. Настройки (админы, чат, TZ) — в таблице `settings`, не в коде.
7. **Молчаливых ошибок нет.** Любой не-2xx от Bot API → сообщение в чат с кодом и
   описанием; в handler'ах — try/catch, который пишет об ошибке пользователю.

### ФУНКЦИОНАЛ

**Учёт.** `/vip add @nick [30d] [--to YYYY-MM-DD] [--note …]`, `/vip list`,
`/vip info @nick` (история), `/vip extend @nick [+30d]`, `/vip remove @nick [причина]`,
`/vip keep @nick`, `/vip cancel @nick`, `/vip export` (CSV текстом), `/vip stats`,
`/vip dashboard` (запиненное сообщение, которое бот сам редактирует), `/vip check`,
`/vip admins`, `/vip whoami`, `/vip help`.

**Напоминания.** T−3, T−1, T−0 (после настроенного часа локального времени), «просрочено»
на следующий день, дальше раз в неделю максимум 4 раза, плюс дайджест по понедельникам.
Под каждым сообщением — кнопки: `✅ Снял`, `➕ +30 дн.`, `📅 +7 дн.`, `🙈 Оставить`,
`⏰ Завтра`. `callback_data` — короткий код `v:<action>:<grantId>` в пределах 64 байт,
id записи — 8 символов; никаких длинных «сырых» id.

**Данные.** Таблицы: `vip_grants` (одна строка = один период, продление — новая строка со
ссылкой `renewedFrom`), `notifications` (журнал + уникальность), `audit_log`, `settings`
(key/value). Частичный уникальный индекс на «один активный период на человека».

### ТЕСТЫ (обязательны до фичи)

1. `daysLeft` по календарным дням, включая переход на летнее время.
2. Правила напоминаний: T−3/T−1/T−0 с порогом по часу; «в промежуточные дни молчим»;
   просрочка; недельная эскалация и её потолок; `sent` блокирует повтор; snooze глушит.
3. Продление «стопкой» и от сегодня, в том числе для уже истёкшей записи.
4. Разбор команд: `--to`, `--note`, `@Nick` → `nick`, `/vip@Bot`, мусорный текст → игнор.
5. Дайджест: понедельник после часа X, ровно раз в день.
6. Утилиты: нарезка длинного текста без потери строк, экранирование CSV-кавычек.

Плюс smoke-проверка: все модули проекта импортируются с заглушкой `sdk` (на платформе
битый импорт — это ошибка деплоя, а не рантайма).

### DEFINITION OF DONE

- `npm test` и `npm run smoke` — зелёные без доступа к платформе.
- `npx tgcloud push` + `npx tgcloud migrate` проходят; `npx tgcloud webhook` → `in sync`.
- `README.md` в проекте: включить Serverless в BotFather, где взять CLI-токен, деплой,
  миграции, как включить внешний крон, что делать при рассинхроне (`status/diff/pull`).
- `AGENTS.md` с правилами платформы (их читает и человек, и следующий агент).
- Ручной чек-лист на живом боте: `/start` → владелец назначен; `/vip add` → пришло
  сообщение с копируемой командой; повторный тик → второго сообщения нет; кнопки
  «снял/продлить/завтра» меняют состояние; `/vip export` не превышает лимит сообщения.

### ФОРМАТ ОТВЕТА

1. 5–10 строк «как понял задачу» + принятые за меня решения.
2. Дерево файлов с одной строкой описания на файл.
3. Код полными файлами (без «…» и «допиши сам»).
4. `schema.js`, тесты и фактический вывод прогона.
5. Чек-лист ручной проверки + «что осталось за рамками и почему».

### НЕ ДЕЛАЙ

- Не проектируй приём вебхуков Twitch и «сверку списка VIP» — на этой платформе нет
  входящего HTTP, а без токена стримера нет и данных.
- Не пиши планировщик на `setTimeout`/`setInterval` и не пытайся «держать процесс».
- Не используй npm-пакеты, `fs`, `crypto`, `process.env`, `node:*` — их нет.
- Не делай `setWebhook`, не трогай `.tgcloud/`, не удаляй строки из БД.
- Не храни настройки в коде: только `settings`.
- Не отправляй CSV файлом — платформа не отдаёт документы.
- Не полагайся на порядок выполнения: тик может прийти одновременно из двух мест.
