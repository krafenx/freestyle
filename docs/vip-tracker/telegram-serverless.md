# План под Telegram Serverless (tgcloud)

Проверено по `@tgcloud/cli@0.2.0` (исходники + шаблоны, которые CLI скаффолдит),
публичной документации платформы и двум сторонним проектам. Всё, что ниже помечено
«нет», действительно отсутствует — это не догадки.

## Что платформа даёт из коробки

| Что | Детали |
|---|---|
| Исполнение | JS-модули в изолированном V8, рядом с Bot API. Ни сервера, ни контейнеров |
| Входящие события | `tgcloud/handlers/<тип апдейта>.js` — один файл на тип (`message`, `callback_query`, `inline_query`, …), платформа сама держит webhook |
| HTTP-ручки | `tgcloud/endpoints/<имя>.js` → `POST /api/<имя>` для Mini App, `ctx.initData` платформа проверяет сама |
| База | встроенная SQLite: `tgcloud/schema.js` в DSL, миграции `npx tgcloud migrate`, ~0.5 ГБ |
| SDK | `import { db, api, fetch, BotApiError } from 'sdk'` — Bot API без обёрток, любой метод, `fetch` для внешних запросов |
| Деплой | `npx tgcloud push` / `status` / `diff` / `pull` / `run` / `webhook`; токен CLI (не токен бота) из BotFather → Serverless → CLI Access |
| Для ИИ | проект скаффолдится вместе с `AGENTS.md` и справочником SDK — агенту не нужно ничего додумывать |

## Два ограничения, которые меняют продукт

### 1. Нет таймера

Код исполняется **только** на апдейт Telegram или на вызов модуля через management API.
В списке возможностей платформы 27 обработчиков, и ни один не временной. Значит
«напомнить в 10:00» само по себе не произойдёт.

Решение — триггерить тик из трёх мест (см. `lib/tick.js`):

| Триггер | Пунктуальность | Цена |
|---|---|---|
| Ленивый тик в `handlers/*` (любое сообщение боту) | «когда бота тронули» | ноль, полностью нативно |
| `endpoints/tick` через `npx tgcloud run` из внешнего крона | ±5–20 мин (GitHub Actions) | один секрет `TGCLOUD_TOKEN` + cron |
| Кнопка «Проверить» / `/vip check` | вручную | ноль |

Идемпотентность держит не планировщик, а база: `UNIQUE(grant_id, kind)` в `notifications`
и `claimNotification()` перед отправкой. Поэтому лишний тик безвреден — это ключевое
свойство, иначе три источника запуска превратились бы в спам.

### 2. Нет произвольного входящего HTTP

Нельзя поднять эндпоинт `POST /twitch/eventsub` и принимать вебхуки Twitch: снаружи
платформа принимает только Telegram-апдейты и вызовы Mini App с проверенным `initData`.
Следствия:

- **EventSub на редимы каналпоинтов недоступен** → автоматически «поймать» выдачу VIP нельзя.
  Для выбранного режима (модератор выдаёт командой сам) это не потеря, а совпадение:
  источник правды — команда в Telegram.
- **Twitch API не используется вообще** — ни выдача, ни снятие, ни сверка списка VIP.
  Решение заказчика: записал в боте, выдал командой в чате, дождался напоминания, снял.
  Отсюда следствия: у записей нет `user_id` (только ник текстом), инвариант «один активный
  период» висит на `login`, а `--to`/срок считает бот, а не Twitch.
- Если когда-нибудь понадобится авто-выдача или EventSub — это отдельный маленький
  сервис (VPS/Cloudflare/Deno), который дергает бота через `tgcloud run`. Смешивать
  не нужно: у платформы нет для этого поверхности, и в текущем объёме это не планируется.

## Итоговая архитектура

```
                 Telegram (апдейты)                    внешний крон (опционально)
                        │                                        │
                        ▼                                        ▼
        handlers/message.js  handlers/callback_query.js   npx tgcloud run endpoints/tick
                        │                                        │
                        └──────────────┬─────────────────────────┘
                                       ▼
                              lib/commands.js  ← команды, кнопки, аудит
                                       │
                        ┌──────────────┴──────────────┐
                        ▼                             ▼
                  lib/tick.js                  lib/db.js
             (статусы, напоминания,        (вся работа с SQLite,
              дайджест, дашборд)            идемпотентность)
                        │                             │
                        └──────────► lib/core.js ◄────┘
                              чистая логика: даты, TZ,
                              разбор команд, тексты
                              (единственный модуль,
                               который гоняется в Node)
```

`lib/core.js` без `sdk` — это не стилистика, а возможность тестировать самое
ошибкоопасное (даты, DST, «какое напоминание пора») обычным `node --test`, без доступа
к платформе. Всё, что требует `sdk`, проверяется только через `tgcloud run`.

## Как выглядит работа модератора

1. `/vip add @nick` → бот: «записал, до 12.12, выдай в чате: `/vip nick`» (тап — копирование).
2. Ты вставляешь команду в чат Twitch. Два действия, дальше бот сам.
3. За 3 дня / за день / в день истечения — сообщение с кнопками.
4. «✅ Снял» → запись закрыта, в чат уходит `/unvip nick` для копирования.
   «➕ +30» → продлено от текущего конца срока (дни не сгорают).
   «🙈 Оставить» → тихое напоминание через неделю, без эскалации.

## Риски, которые надо принять осознанно

- **Ранний доступ.** Serverless включается в BotFather и может подождать; API/лимиты
  ещё меняются. `tgcloud status/diff/pull` покажут расхождение локального и облака.
- **`tgcloud run` исполняет локальный код**, а не задеплоенный. Внешний крон должен
  работать ровно на том коммите, который задеплоен (в workflow — `checkout` + тот же ref).
- **GitHub Actions**: расписание может запаздывать на 5–20 минут, а после 60 дней без
  активности в репозитории schedule отключается. Если это критично — cron-job.org.
- **CPU ~3 с на вызов** и ~0.5 ГБ SQLite. Для сотни VIP этого хватает с запасом,
  но массовый импорт CSV придётся делать пачками.
- **Нет выгрузки файлов** → экспорт только текстом; «бэкап» = `/vip export` в чат.
- **Первый, кто написал боту, становится владельцем.** Бот должен быть непубличным;
  владельца можно переписать в таблице `settings` (ключ `config.ownerId`).

## Если платформа не подойдёт

`lib/core.js` (даты, правила напоминаний, тексты) переносится без изменений — он ни от
чего не зависит. Замена `lib/db.js` на Drizzle/SQLite и `sdk/api` на grammY — это
~150 строк. Дороже всего переписывать не логику, а обвязку; поэтому она и вынесена
в два тонких файла.
