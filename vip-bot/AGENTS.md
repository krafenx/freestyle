# AGENTS.md

Ориентация для ИИ-агентов и людей. Полный справочник SDK — в `docs/tgcloud-sdk.md`
(его кладёт `tgcloud init`), правила платформы коротко — здесь.

## Что это за проект

Бот учёта Twitch-VIP на месяц. Работает на **Telegram Serverless** (tgcloud):
JavaScript-модули исполняются в V8-изоляте внутри облака Telegram, база — встроенная
SQLite. `tgcloud` синхронизирует локальную папку с облаком (аналог `wrangler` + `drizzle-kit`).

**Не путать:** этот проект НЕ выдаёт VIP через Twitch API. Helix `POST /channels/vips`
требует токен самого стримера (`broadcaster_id` должен совпадать с владельцем токена),
а заказчик — модератор. Он выдаёт VIP командой в чате, бот ведёт учёт и напоминает.

## Раскладка

| Путь | Что |
|---|---|
| `tgcloud/schema.js` | Схема БД, таблицы — именованные экспорты. Один файл в корне модульного дерева. |
| `tgcloud/lib/` | Общий код. Вложенность разрешена. **Не исполняется** платформой напрямую. |
| `tgcloud/handlers/` | Обработчики апдейтов, ровно один уровень, имя = тип апдейта Telegram (`message`, `callback_query`, …). Исполняются. |
| `tgcloud/endpoints/` | Вызываются Mini App (`POST /api/<имя>`); сюда же смотрит `tgcloud run`. |
| `test/` | Тесты чистой логики (`npm test`), в облако не уезжают. |
| `tools/smoke.mjs` | Проверка графа модулей (`npm run smoke`) — ловит битые импорты до `push`. |
| `.tgcloud/` | Машинное состояние CLI. Не читать, не править, в git не добавлять. |

## Правила, на которых легко споткнуться

1. **Импорт только по bare-имени:** `from 'sdk'`, `from 'schema'`, `from 'lib/core'`.
   Относительные пути и расширение `.js` — ошибка сборки.
2. **Нет npm-пакетов, нет файловой системы.** Всё, что нужно, — в `sdk` и в этом проекте.
   Поэтому даты/часовые пояса считаются через `Intl`, а не Luxon.
3. **Каждый вызов БД асинхронный.** Забытый `await` вернёт билдер, а не строки.
4. **Внешних ключей нет.** `.references()` бросает исключение. Целостность — в коде
   (`lib/db.js`), удалений нет вообще: только смена `status`.
5. **Нет таймера.** Код запускается только на апдейт или на `/run`. Напоминания
   идут через `runTick()` из `lib/tick.js`, а он вызывается из ленивого тика
   (handler'ы), из `endpoints/tick` (внешний крон) и с кнопки.
6. **Идемпотентность обязательна.** Единственная защита от дублей — уникальный индекс
   `UNIQUE(grant_id, kind)` в `notifications` и `claimNotification()` перед отправкой.
   Любой новый вид уведомления должен идти через него же.
7. **`push` не меняет базу.** Схема применяется только `npx tgcloud migrate`.
   Удаление колонок — лишь через `.deprecated('причина')`.
8. **Webhook'ом управляет платформа.** Не вызывать `setWebhook` сырым токеном бота:
   это рассинхронизирует платформу (`npx tgcloud webhook` покажет расхождение).
9. **Файлы отдавать нельзя** (загрузка/выгрузка документов не поддерживается) —
   поэтому `/vip export` отправляет CSV текстом в `<pre>`, порезанным на части.
10. **Никаких секретов в коде:** админы, чат и часовой пояс живут в таблице `settings`.

## Проверки перед деплоем

```bash
npm test            # чистая логика: даты, разбор команд, выбор напоминаний
npm run smoke       # все модули импортируются (заглушка sdk в node_modules)
npx tgcloud status  # что изменилось относительно облака
npx tgcloud push    # деплой кода
npx tgcloud migrate # если менял schema.js
```
