# vip-bot — учёт Twitch VIP на месяц (Telegram Serverless)

Telegram-бот, который помнит, кому выдан VIP, считает срок и присылает напоминания.
Работает целиком на Telegram Serverless: нет сервера, нет VPS, база — встроенная SQLite.

## Чего бот принципиально не делает

**Twitch API не используется вообще** — ни выдача, ни снятие, ни сверка списка VIP,
ни OAuth. Это осознанное решение: Helix всё равно требует токен самого стримера
(`broadcaster_id` должен совпадать с владельцем токена, модератор получает 401/403),
а пользы от API в этой задаче ноль.

Что бот делает вместо этого:

- на `/vip add @nick` отвечает готовой командой `/vip nick` для копирования — выдаёшь ты;
- в каждом напоминании уже лежит `<code>/unvip ник</code>` — снятие в один тап;
- кнопки «✅ Снял», «➕ +30 дн.», «📅 +7», «🙈 Оставить», «⏰ Завтра» меняют только учёт;
- ведёт историю, аудит и экспорт, чтобы «кто и когда выдал/снял» не жило в голове.

Ник — просто текст: бот не резолвит его в Twitch user id, поэтому проверяет только формат
(латиница/цифры/`_`, 4–25 символов) и хранит как есть.

## Установка (15 минут)

1. **Включить Serverless.** В @BotFather → ваш бот → **Settings → Serverless** →
   включить (ранний доступ; иногда приходится подождать).
2. **Взять CLI-токен.** @BotFather → ваш бот → **Serverless → CLI Access** →
   Access token. Это **не** обычный токен бота; выглядит как `app12345:xxxxx`.
3. **Забрать проект и привязать к боту:**

```bash
cd vip-bot
npm install                      # @tgcloud/cli как devDependency
npx tgcloud login                # вставить CLI-токен (или TGCLOUD_TOKEN=… )
npx tgcloud push                 # деплой кода
npx tgcloud migrate              # создать таблицы (push базу не меняет!)
```

4. **Написать боту `/start`** в личке или в приватной группе модераторов.
   Первый написавший становится владельцем, а его чат — чатом для напоминаний.
   Остальных добавить: `/vip admins add <tg_id>` (свой id даёт `/vip whoami`).

Проверить, что webhook платформы синхронный: `npx tgcloud webhook`
(должно быть `in sync`). Руками `setWebhook` не вызывать — платформа этим управляет.

## Напоминания: главная особенность платформы

**На Serverless нет таймера.** Код исполняется только на входящий апдейт или на вызов
модуля через management API. Поэтому `lib/tick.js` вызывается из трёх мест:

| Откуда | Когда работает | Плюсы / минусы |
|---|---|---|
| Ленивый тик в `handlers/*` | любое сообщение боту (в т.ч. обычный текст в чате модераторов) | бесплатно и нативно; «когда бота тронули», зато с догоном пропущенного |
| `endpoints/tick` через `npx tgcloud run` | внешний крон (см. ниже) | пунктуально; нужен один секрет и один cron |
| Кнопка «Проверить» / `/vip check` | по требованию | ручная страховка |

Внешний «будильник» — на выбор, всё сводится к одной команде:

```bash
# GitHub Actions (файл .github/workflows/reminders.yml уже в проекте)
#   положить секрет репозитория TGCLOUD_TOKEN → тик каждый час
# или crontab на любой машине:
0 * * * *  cd /path/to/vip-bot && TGCLOUD_TOKEN=app12345:xxx npx tgcloud run endpoints/tick
```

> Важно: `tgcloud run` исполняет **локальные** файлы, а не задеплоенные. Крон должен
> работать на том же коммите, что и последний `push` (в workflow это гарантирует checkout).
> GitHub может задерживать расписание на 5–20 минут и отключает schedule после 60 дней
> без активности в репозитории — если это критично, используй cron-job.org.

### Будет ли напоминание «само»?

| Что настроено | Когда придёт напоминание |
|---|---|
| только `push` + `migrate` | при следующем **любом сообщении** боту (команда или просто текст в чате модераторов) — тик срабатывает и догоняет пропущенное |
| плюс `cron` (Actions/crontab) | в течение часа после нужного момента, обычно через 5–20 минут |
| ничего и никто не пишет | не придёт: на платформе физически нет таймера, который разбудит код |

Поэтому важное свойство логики: **пропущенное окно не теряется**. Если бот «проспал»
день T−0, при следующем пробуждении он всё равно пришлёт «просрочено — сними»
(и дальше раз в неделю, максимум 4 раза). За один тик — максимум одно сообщение,
так что догон не превращается в пачку.

Дубли исключены в любом случае: перед отправкой напоминание «столбится» в таблице
`notifications` уникальным индексом `UNIQUE(grant_id, kind)`, поэтому три тика подряд
дадут ровно одно сообщение, а ленивый тик к тому же не чаще раза в 5 минут.

## Команды

```
/vip add @nick [30d] [--to 2026-12-01] [--note «за 5000 битсов»]
/vip list [--all]          активные, ближайшие сверху
/vip info @nick            вся история по человеку
/vip extend @nick [+30d]   продление (по умолчанию «стопкой» от текущего конца)
/vip remove @nick [причина]
/vip keep @nick            «оставляем», напомню через неделю
/vip cancel @nick          отменить ошибочную запись (остаётся в истории)
/vip export                CSV текстом (файлы платформа отдавать не умеет)
/vip stats                 сводка
/vip dashboard             закрепить сообщение-дашборд, которое бот сам правит
/vip check                 прогнать тик руками
/vip admins [add|del id]   доступ
/vip whoami                свой tg id и chat id
```

Напоминания: за 3 дня, за 1 день, в день истечения (после 10:00 локального),
«просрочено» на следующий день, дальше раз в неделю (максимум 4 раза),
плюс дайджест по понедельникам.

## Локальные проверки

```bash
npm test          # 28 тестов чистой логики (даты, DST, разбор команд, выбор напоминаний)
npm run smoke     # все модули импортируются (подсовывает заглушку sdk)
npx tgcloud run handlers/message '{"chat":{"id":1},"text":"/vip list","from":{"id":1}}'
npx tgcloud run endpoints/tick
```

Тесты и smoke работают без доступа к платформе; всё, что требует `sdk`, проверяется
только через `tgcloud run` (эмулятора SDK локально нет).

## Ограничения платформы, которые видны в коде

| Ограничение | Как обойдено |
|---|---|
| нет npm, нет `fs` | даты/пояса — на `Intl` (`lib/core.js`), UUID-подобные id — из `Math.random` |
| нет внешних ключей | целостность в `lib/db.js`, ничего не удаляем физически |
| нет таймера | ленивый тик + `endpoints/tick` + внешний крон |
| нет загрузки/выгрузки файлов | `/vip export` — CSV текстом в `<pre>`, порезанный по 3500 символов |
| ~3 с CPU на вызов | тик читает только открытые записи, ~1 запрос на запись |
| ранний доступ | платформа может меняться: `npx tgcloud status/diff/pull` покажут расхождения |

## Что дальше

1. Резервная копия: платформа не отдаёт дампы, поэтому `/vip export` раз в месяц в чат —
   единственный «бэкап» без внешних костылей.
2. Внешний крон (`.github/workflows/reminders.yml`), если нужны пунктуальные T−0.
3. Всё остальное — по мере того, как выяснится, чего не хватает в реальной работе.
