# Крон для напоминаний: включить за 3 шага

Бот на Telegram Serverless спит и просыпается, когда ему пишут. Таймера на платформе нет,
поэтому напоминания «само в 10:00» кто-то должен инициировать снаружи. Этот «кто-то» — крон,
и всё, что ему нужно делать: раз в час выполнить

```bash
npx tgcloud run endpoints/tick
```

Дальше бот сам смотрит сроки, рассылает напоминания и обновляет дашборд. Пропущенные запуски
не страшны: логика догоняет пропущенные окна (см. `README.md`).

---

## Вариант 1. GitHub Actions (рекомендую)

Файл уже в проекте: `.github/workflows/reminders.yml` — расписание каждый час, кнопка
ручного запуска, защита от отсутствующего секрета.

### Шаг 1. Взять CLI-токен

@BotFather → твой бот → **Serverless** → **CLI Access** → скопировать access token.
Он выглядит как `app12345:abcdef...`. **Это не токен бота** (тот `12345:AAE...`) — их легко
перепутать, и тогда крон будет падать с 401.

### Шаг 2. Положить его в секреты репозитория

```bash
gh secret set TGCLOUD_TOKEN --repo krafenx/freestyle
# команда попросит вставить значение и не сохранит его в shell history
```

Или через веб: репозиторий → Settings → Secrets and variables → Actions →
New repository secret → имя `TGCLOUD_TOKEN`.

### Шаг 3. Убедиться, что workflow лежит в `main`, и проверить руками

GitHub запускает расписание **только из ветки по умолчанию**. Пока файл не в `main`,
крона нет.

```bash
gh workflow list --repo krafenx/freestyle                # должен быть vip-reminders
gh workflow run vip-reminders --repo krafenx/freestyle   # ручной запуск
gh run list --workflow=vip-reminders --limit 5           # через минуту: success?
```

В логе успешного запуска будет строка вида `проверил: напоминаний 0 · дайджест отправлен` —
это значит, что бот проснулся и всё посчитал.

### Что нужно знать про этот вариант

| Нюанс | Что делать |
|---|---|
| Расписание может опаздывать на 5–20 минут, иногда запуск пропускается | логика догоняет: отправленное не повторится, пропущенное придёт на следующем тике |
| GitHub **отключает** scheduled workflow после 60 дней без активности в репозитории | придёт письмо; включить кнопкой «Enable workflow» или `gh workflow enable vip-reminders`. Любой коммит тоже сбрасывает счётчик |
| Репозиторий приватный → минуты Actions расходуются (2 000/мес на Free) | час × 30 дней = ~730 запусков по 30–50 с ≈ 500–600 минут. Влезает. Хочешь экономить — поставь `0 */3 * * *`, тогда T−0 может опоздать до 3 часов, но не потеряется |
| Изменения workflow в ветке не влияют на крон | правишь расписание — сначала мёржишь в `main` |
| Секрет = полный контроль над ботом | не печатать в логи, не коммитить, ротация — BotFather → Serverless → CLI Access |

## Вариант 2. crontab на любой всегда включённой машине

VPS, Raspberry Pi, домашний сервер, старый ноутбук — годится всё, где есть Node.js 18+.

```bash
cd vip-bot
chmod +x scripts/tick.sh
mkdir -p ~/.config/vip-bot && printf '%s' 'app12345:xxxxx' > ~/.config/vip-bot/token
chmod 600 ~/.config/vip-bot/token
./scripts/tick.sh          # проверить руками
crontab -e                 # и добавить строку:
# 0 * * * *  /полный/путь/до/vip-bot/scripts/tick.sh >> /tmp/vip-bot.log 2>&1
```

`scripts/tick.sh` сам находит токен (env или файл), проверяет наличие `npx` и падает
с понятным кодом, если что-то не так. Логи — в `/tmp/vip-bot.log`.

Плюсы: никаких лимитов и задержек, полный контроль. Минус: машина должна быть включена,
и обновлять код надо самому (`git pull` + `npx tgcloud push`).

## Вариант 3. «Дёргалки URL» (cron-job.org и подобные)

Честно: сюда подходит плохо. Management API платформы требует `POST` с JSON-телом и заголовком
`Authorization: Bearer app<id>:<secret>`, а бесплатные тарифы таких сервисов обычно не дают
ни тела, ни кастомных заголовков. Если очень нужен именно такой сервис — проще поставить
10 строк на Cloudflare/Deno, но это уже вторая инфраструктура ради одного `fetch`.

---

## Как убедиться, что всё живо

1. `gh run list --workflow=vip-reminders --limit 5` — запуски зелёные.
2. В боте `/vip check` — отвечает `🔄 проверил: напоминаний N`.
3. Раз в неделю-две заглядывать в Actions: если job стал красным, GitHub пришлёт письмо
   (по умолчанию — владельцу репозитория).

## Если сломалось

| Что видно в логе | Причина и лечение |
|---|---|
| `TGCLOUD_TOKEN не задан — тик пропущен` | секрет не создан или назван иначе |
| `401` / `invalid token` | взял обычный токен бота вместо CLI-token, либо токен отозвали в BotFather |
| `тик не выполнена: нет chatId` | боту не написали `/start` после деплоя — некому слать |
| `тик с ошибками: 403 ...` | бота удалили из группы модераторов (или он не админ, если группа закрыта) |
| `Module not found: endpoints/tick` | запуск не из папки проекта или ты на другом коммите: крон должен работать на том же коде, что задеплоен |
| запуски есть, напоминаний нет | это нормально: тик шлёт только то, что попало в окно (T−3 / T−1 / T−0 / просрочка / неделя) |
